3. ARCHITECTURE

Use a small Python package and CLI. A notebook may later display results, but
must not contain the core experiment implementation. Plan these modules:

- data.py: original prompt sampling, role metadata, counterfactual labels,
  serialization, and fixed train/test splits.
- tokenization.py: tokenizer loading, right padding, attention masks, character
  offsets, name token spans, and encoded examples.
- positions.py: convert named anchors and relative offsets into per-example
  token indices; no sampling, optimization, or plotting.
- intervention.py: build the pyvene intervention and share one intervention
  forward function between training and evaluation.
- train.py: train alignment parameters while keeping language-model weights
  frozen; preserve gradient flow needed to learn the intervention.
- evaluate.py: factual IOI accuracy, counterfactual IIA, per-example predictions,
  and readout at the last valid base token.
- experiment.py: run_condition() for one condition and run_sweep() for several.
- plot.py: render figures from saved experiment results without training.
- cli.py: command-line entry points for each phase.

Keep configuration under configs/, generated fixed samples under data/generated/,
and audit/experiment outputs under outputs/. Resolve paths relative to explicit
project/config locations, not an accidental working directory. Create only the

4. DATA AND POSITION CONTRACTS

Preserve the original POSITION-task sampling rules:
- Training: base ABB/BAB crossed with source ABB/BAB, 50 examples per pairing,
  giving 200 base/source pairs.
- Test: ABB to BAB and BAB to ABB, 50 examples each, giving 100 pairs.
- Names, objects, and places: original first-half/second-half split.
- Templates: original first two for training and remaining templates for test.

Generate once, save train.jsonl and test.jsonl, and reuse the saved examples
across experiment conditions. Record seed, generator revision, tokenizer
identity/revision, and file hashes. A seed alone is not a saved dataset. Inspect
unordered-set iteration or other nondeterminism; document any deterministic
implementation change. Do not claim these are my historical 200 examples.

Each pair must retain a stable ID, base/source text, template identifier,
pattern information, each prompt's factual IO name and subject, occurrence-level
name character spans, and the counterfactual answer name. Preserve names as text
as well as token IDs, so the same examples can later use another tokenizer.

Distinguish three concepts explicitly:
- target_variable: the high-level causal variable, initially "position";
- intervention_location: the activation site, e.g. IO or END with an offset;
- readout_location: the last valid base token, even when intervening at N-2.

The original io_pos and s1_pos describe first/second NAME order, not token
indices. Do not use them directly as tensor positions. For the POSITION task,
construct the counterfactual answer by applying the source position variable to
the base names, following upstream logic. It is not always the source answer.

Define anchors for each prompt independently:
- IO / GOAL_NAME: the occurrence of that prompt's factual indirect-object name
  inside its input. This is not a generated answer or a counterfactual target.
- S1: first occurrence of the subject.
- S2: second occurrence of the subject.
- END / N: last non-padding input token.

Track character spans during prompt construction and map them to token spans
using offsets from a compatible fast tokenizer. Verify that token IDs match
the intended GPT-2 tokenization. Do not locate repeated names by searching for
the first matching token ID. Store full spans; the initial scalar name anchor
is the last token of the selected span. Record this policy explicitly.

For right-padded input: N = attention_mask.sum() - 1; END with offset -k maps
to N-k. Compute this separately for every base and source example. A base of
18 tokens and source of 22 tokens have N-1 indices 16 and 20, respectively.
Do not force all examples to 18 tokens. Do not truncate, discard, or rewrite
prompts merely to satisfy the old assertion. Padding is not part of the prompt.
Do not append the target answer to the model input. Reject invalid anchors or
out-of-range offsets with sample IDs and actionable diagnostics.

Retain separate base and source position arrays in the batching API. Pass each
side's attention mask in later model/pyvene calls. Evaluate next-token predictions
at each base example's N, never blindly at the batch tensor's final column.

Initially use single-token answer evaluation. Check the actual continuation
tokenization, including the leading space and prompt boundary. If an answer
requires multiple tokens, preserve and report the example and mark this as an
unsupported evaluation case. Never silently use only its first token.
