### Current research context

- [evidence] DAS on the IOI POSITION variable (whether the subject is the
  first or the second name of the opening clause: ABB vs BAB). An orthogonal
  matrix U (d × r) is learned at one layer and one token location (N, the
  last token) on `block_output`; the intervention swaps source into base
  within span(U). Only `block_output` exists in code: `configs/schema.json`
  fixes the component and `build_intervention` hard-codes it. The token
  location is already configurable (IO, S1, S2, END, N ± k).
- [evidence] GPT-2 Small (layer-sweep): signal only at layers 7–9; layer 8
  validation IIA 0.83.
- [evidence] GPT-2 Medium: peak at layer 14 for every rank (rank 1–8:
  0.28–0.30) and every training size and budget tried (0.25–0.32).
- [evidence] Replacing the whole `block_output` vector at N: 0.70 at Small
  layer 8, at most 0.105 in Medium. DAS exceeds this in both models.
- [evidence] Not run: GPT-2 Small rank sweep, learning-rate check,
  object-names, 6 of 16 data-scale configs.
- Reading rule: high IIA shows that the intervention produces the
  counterfactual behavior, not that the information is stored only there.
  Low IIA does not show that the information is absent; it may be
  distributed, redundant, or rewritten later in the model.

### Concepts I am working to understand [learning]

1. The forward pass: token and position embeddings → per layer, LayerNorm
   → attention → add to the residual, then LayerNorm → MLP → add → final
   LayerNorm → unembedding → next-token logits at the readout position.
2. Fixed weights (embeddings, W_Q/K/V/O, MLP in/out, LayerNorm, unembedding)
   vs input-dependent activations (residual stream, attention patterns, MLP
   hidden units) vs the learned DAS matrix U.
3. The separate axes: token position, layer, attention head (n_head ×
   64), hidden dimension (d_model 768 / 1024; MLP hidden 3072 / 4096 for
   Small / Medium), and DAS rank r (the number of columns of U).
4. Where each component sits (pyvene 0.1.8 GPT-2 hooks):

   | Component | Hook point | Size (Small / Medium) | Relation to LayerNorm and residual |
   | --- | --- | --- | --- |
   | `block_input` | input of block `h[l]` | 768 / 1024 | residual stream, before `ln_1` |
   | `attention_output` | output of `attn.resid_dropout` | 768 / 1024 | attention branch, before it is added to the residual |
   | resid_mid | input of `ln_2` (no pyvene component) | 768 / 1024 | residual after the attention add, before `ln_2` |
   | `mlp_input` | input of `h[l].mlp` | 768 / 1024 | after `ln_2` |
   | `mlp_activation` | output of `mlp.act` (GELU) | 3072 / 4096 | inside the MLP |
   | `mlp_output` | output of `h[l].mlp` | 768 / 1024 | MLP branch, before it is added to the residual |
   | `block_output` | output of block `h[l]` | 768 / 1024 | residual after both adds |

5. The DAS swap: h' = h_base + U Uᵀ (h_source − h_base). It replaces base's
   coordinates in span(U) with source's, keeps base's orthogonal
   complement, and the patched activation then runs through the rest of the
   model.
6. Why rank 1 is a direction that may spread over many coordinates, not a
   single neuron (one coordinate of `mlp_activation`).
7. Three different "positions": the POSITION causal variable, the token
   location where we intervene (N), and GPT-2's learned position embedding.
   The intervention swaps an activation at N; it does not edit position
   embeddings.

### Proposed next research question [proposal]

Extend "At which layer does `block_output` contain a subspace that supports
the POSITION counterfactual swap?" to "Within a layer, can the attention
branch, the MLP branch, or the MLP hidden representation also support the
swap, and how do their layer–IIA profiles differ?" This adds to the current
plan rather than replacing it. Medium motivates it: the whole `block_output`
vector at N carries little of the decision (0.105), so the signal may be
written by components and positions that a single residual site misses.

### Candidate experiments and their rationale [proposal]

Each step runs only if the previous one gives the stated trigger.

1. **Full-vector patch map (no training).** For `block_output`,
   `attention_output`, `mlp_output`, and `mlp_activation`, replace the whole
   vector at N with the source's, at every layer of Small and Medium, on
   validation. It costs minutes, shows where whole-component swaps already
   move the output, and gives the reference each DAS result is read against:
   DAS far above the full patch is the subspace-illusion warning seen at
   `block_output`.
2. **DAS component comparison, GPT-2 Small first.** The same four
   components, every layer, N, rank 1, legacy 200-pair training set, 10
   epochs, seeds 42/43/44, validation selection per component, test after
   the lock (3 new components × 12 layers × 3 seeds = 108 runs). U is
   trained separately per component and never shared (sizes differ: 768 × r
   vs 3072 × r). Record U's size, both baselines, the step-1 full patch, and
   training curves. Small first because its signal is strong and localized
   and the IOI circuit (Wang et al., 2022) predicts where attention writes
   the signal, so the method can be checked against an expectation.
   - Then Medium over all 24 layers with the same settings. A scan only
     around layer 14 could miss a peak of another component at another
     layer.
   - Caveat: Makelov et al. (2023) demonstrate the subspace illusion with
     MLP activations in IOI; `mlp_activation` results need the full-patch
     reference and their proposed checks before interpretation.
3. **Triggers for finer analysis.**
   - Head-level (`head_attention_value_output`, 64 dimensions per head):
     if `attention_output` at some layer approaches `block_output` IIA at
     that layer and clearly exceeds its baselines.
   - Q / K / V: only if one head carries most of the effect, to separate
     where it attends (Q, K) from what it reads (V). V lives at the key
     positions (the name tokens), not at N, so this also needs other token
     locations.
   - Other token locations (S2, IO, S1, N − k; configuration only): if the
     component maps at N stay weak in Medium, or a head at N reads the
     signal from earlier positions.
   - resid_mid (needs a custom hook): if `attention_output` and
     `mlp_output` at the same layer disagree and the question is whether the
     signal exists after the attention add but before the MLP.
   - Attention probabilities are excluded from the first round (causal
     mask, probability constraints, and key axes that vary with prompt
     length).

How this connects to the current tasks:

- rank-sweep: rank did not matter for Medium `block_output`, so step 2
  fixes rank 1. That finding may not carry over to `mlp_activation`
  (3072 / 4096 dimensions), so a rank 1 vs 4 check at each component's peak
  layer is proposed.
- data-scale: training size did not matter for Medium `block_output`, so
  step 2 uses the legacy 200-pair set, keeping it comparable with
  layer-sweep. The 6 cancelled data-scale configs are not needed for this
  question.
- Optimization check: component activations differ in scale (for example
  GELU outputs vs residual), so the learning rate tuned on `block_output`
  may not suit them. The planned learning-rate check moves to each
  component's peak layer.
- Per-object reporting: base and source share the object, so a faithful
  POSITION swap at any component should leave the "bone → the" preference
  unchanged. A component that gains IIA on bone prompts by suppressing
  " the" is changing something other than POSITION. Report every component
  per object and with the names-only score.
- Selection groups by layer only, so components need either one config per
  component (works now) or brief
  [grouped-selection-compare](../briefs/2026-10-18-grouped-selection-compare.md).
